# NOWERA Management Workspace

سامانه مدیریت داخلی نَوِرا برای چهار بخش **Lumen، Technoplus، Atlas و Horizen**؛ ساخته‌شده با React، Vite، Supabase Auth و PostgreSQL. رابط فارسی و راست‌چین است.

## راه‌اندازی سریع

### ۱. دیتابیس Supabase را آماده کن

1. در [Supabase](https://supabase.com/) یک پروژه بساز یا پروژه فعلی‌ات را باز کن.
2. وارد **SQL Editor → New query** شو، فایل `supabase/schema.sql` این پروژه را باز کن، **کل** محتوایش را کپی کن و Run بزن. این فایل روی پروژه‌ی خالی و روی پروژه‌ای که نسخه‌ی قدیمی‌تر NOWERA را دارد، هر دو کار می‌کند (جدول‌های قدیمی را ارتقا می‌دهد و تریگر/تابع/policy باقی‌مانده از نسخه‌های قبل را پاک و دوباره می‌سازد) و هر چند بار اجرا شود مشکلی نیست.
   **مهم:** در پایان اجرا یک جدول چک‌لیست نمایش داده می‌شود. همه‌ی ردیف‌ها باید `OK` باشند. اگر به‌جای جدول، یک پیام قرمز **ERROR** دیدی، یعنی هیچ تغییری ذخیره نشده (کل اسکریپت یک تراکنش است)؛ متن خطا را بررسی کن. اسکریپت `supabase/verify.sql` همین چک‌لیست را بدون تغییر دادن چیزی هر زمان اجرا می‌کند.
3. در **Authentication → Sign In / Providers → Email** ارائه‌دهنده‌ی **Email** را روشن نگه دار و گزینه‌ی **Confirm email** را خاموش کن تا بعد از ثبت‌نام ورود فوری ممکن باشد. ثبت‌نام عمومی (**Allow new users to sign up**) نیز باید روشن باشد.
4. ارائه‌دهنده‌ی **Phone** می‌تواند خاموش بماند؛ این نسخه برای ورود به SMS یا سرویس ارسال پیامک نیاز ندارد. فرم سایت همچنان شماره موبایل می‌گیرد و کد یک شناسه‌ی داخلی ایمیلی بر اساس آن تولید می‌کند.
5. از **Project Settings → API**، مقدار **Project URL** و کلید **Publishable** یا کلید قدیمی **anon** را بردار. کلید `service_role` یا `secret` را در این پروژه وارد نکن.

### ۲. اجرا روی کامپیوتر خودت

نصب [Node.js](https://nodejs.org/) نسخه ۲۰ یا جدیدتر کافی است. در ترمینال داخل پوشه پروژه این دستورات را اجرا کن:

```bash
npm install
npm run setup
npm run diagnose
npm run dev
```

- دستور `npm run setup` آدرس و کلید Supabase را از تو می‌گیرد و فایل خصوصی `.env.local` می‌سازد.
- دستور `npm run diagnose` اتصال را واقعاً آزمایش می‌کند و مشخص می‌کند مشکل از URL/کلید، شبکه یا اجرا نشدن schema است.
- بعد از اجرای موفق، آدرس محلی را که Vite در ترمینال چاپ می‌کند باز کن.

اگر `npm run diagnose` اتصال را تأیید کرد ولی ورود یا عضویت مشکل داشت، این موارد را بررسی کن: Email provider روشن باشد، Confirm email خاموش باشد، ثبت‌نام عمومی فعال باشد و نسخه‌ی جدید `supabase/schema.sql` به‌طور کامل اجرا شده باشد.

## مدیر اصلی

**نکته امنیتی:** چون SMS و تأیید شماره عمداً غیرفعال هستند، شماره واردشده به‌تنهایی اثبات هویت نیست و نباید مبنای اعطای نقش مدیر اصلی قرار گیرد. ثبت‌نام‌های جدید به‌صورت عادی عضو می‌شوند؛ نقش مدیر اصلی فقط باید پس از تأیید هویت از یک نشست مورداعتمادِ Supabase SQL Editor واگذار شود. اجرای مجدد schema نقش‌های موجود را حفظ می‌کند و دیگر بر اساس شماره موبایل نقش مدیریتی اعطا نمی‌کند.

برای نصب تازه:
1. حساب موردنظر را در سایت بساز.
2. در Supabase → SQL Editor، شناسه دقیق پروفایل همان حساب را پیدا کن و هویت آن را خارج از سایت تأیید کن:

```sql
select id, full_name, phone, role, created_at
from public.profiles
order by created_at desc;
```

3. فقط پس از تأیید حساب درست، شناسه UUID همان پروفایل را در دستور زیر جایگزین کن و اجرا کن:

```sql
update public.profiles
set role = 'super_admin', is_active = true
where id = 'REPLACE-WITH-VERIFIED-PROFILE-UUID';
```

شناسه را از حسابی که خودت تأیید نکرده‌ای کپی نکن؛ به شماره ثبت‌شده به‌تنهایی اعتماد نکن.

اگر قبلاً ثبت‌نام با خطای `Failed to fetch` مواجه شده، این پرس‌وجو را در SQL Editor اجرا کن:

```sql
select id, phone
from auth.users
where regexp_replace(coalesce(phone, ''), '[^0-9]', '', 'g') = '989333167279';
```

اگر نتیجه‌ای ندارد، حساب اصلاً در Supabase Auth ساخته نشده است؛ اول `npm run diagnose` را موفق کن و سپس دوباره ثبت‌نام کن. اگر حساب وجود دارد اما پروفایل ندارد، فایل `supabase/schema.sql` را دوباره اجرا کن تا backfill انجام شود.

## انتشار با GitHub و Vercel

1. پوشه پروژه را به یک repository در GitHub ارسال کن. فایل `.env.local` به‌وسیله `.gitignore` از Git خارج می‌ماند.
2. در [Vercel](https://vercel.com/) پروژه GitHub را از **Add New → Project** وارد کن.
3. در **Project Settings → Environment Variables** این دو متغیر را اضافه کن:
   - `VITE_SUPABASE_URL` = Project URL در Supabase
   - `VITE_SUPABASE_PUBLISHABLE_KEY` = کلید Publishable یا anon
4. Build command را `npm run build` و Output Directory را `dist` بگذار. Vercel معمولاً این مقادیر را خودکار تشخیص می‌دهد.
5. Deploy کن. هر وقت متغیر محیطی را عوض کردی، یک redeploy انجام بده.

## عیب‌یابی: «schema را اجرا کردم ولی حذف/افزودن عضو کار نمی‌کند»

1. `npm run diagnose` را اجرا کن؛ اگر نام توابعی مثل `deactivate_member` را «وجود ندارد» اعلام کرد، schema در دیتابیس نشسته نیست.
2. `supabase/schema.sql` را کامل اجرا کن و به **انتهای نتیجه** نگاه کن (خطا یا جدول OK/MISSING). نسخه‌های ≤۱٫۳ روی دیتابیس قدیمی وسط کار خطا می‌دادند و چون SQL Editor همه را در یک تراکنش اجرا می‌کند، همه‌چیز Rollback می‌شد.
3. اگر در برنامه نوار قرمز «بخشی از داده‌ها بارگذاری نشد» دیدی، متن لاتین زیر آن علت دقیق است.
4. بعد از اجرا چند ثانیه صبر کن (کش API سوپابیس)، صفحه را Refresh کن.

## چند نکته فنی

- شماره ورود به قالب بین‌المللی `+98...` نرمال می‌شود؛ برای Auth، همین شماره به شناسه‌ی داخلی ثابت `phone-…@login.nowera.invalid` تبدیل می‌شود.
- شماره‌های موبایل در فهرست عمومی نمایش داده نمی‌شوند.
- ورود با شماره و رمز انجام می‌شود؛ در پس‌زمینه از شناسه‌ی ایمیلی غیرقابل‌دریافت (`.invalid`) استفاده می‌شود و هیچ ایمیل یا SMS برای ثبت‌نام لازم نیست. به همین دلیل **Confirm email باید خاموش باشد**.
- «حذف دسترسی» عضو از طریق RPC امن `deactivate_member` انجام می‌شود (تاریخچه حفظ می‌شود). از نسخه ۱٫۴ مدیر اصلی در تب «دسترسی‌بسته» دکمه‌ی **حذف دائمی** هم دارد (`delete_member_permanently`): حساب Auth پاک می‌شود، شماره آزاد می‌شود و پروژه/تسک/رویدادهای ساخته‌شده توسط او به مدیر اصلی منتقل می‌شوند.
- افزودن عضو به تسک (نسخه ۱٫۴) اگر عضو هنوز در پروژه نباشد، او را خودکار در پروژه هم تأیید می‌کند؛ دیگر لازم نیست اول به پروژه اضافه شود.
- برای فعال‌شدن تخصیص/لغو تخصیص مستقیم اعضای پروژه و تسک و همچنین قابلیت‌های قبلی مدیریت اعضا، پس از دریافت نسخه جدید فایل کامل `supabase/schema.sql` را در Supabase SQL Editor دوباره اجرا کن؛ اجرای دوباره‌ی این فایل policyها و RPCها را به‌روزرسانی می‌کند و نقش‌های مدیریتی موجود را حفظ می‌کند. بعد از آن فرانت‌اند را روی Vercel دوباره Deploy کن.
- نقش مدیر اصلی از metadata شماره موبایل یا ثبت‌نام عمومی اعطا نمی‌شود. در نصب تازه، بعد از تأیید هویت در خارج از سایت، UUID حساب را از مسیر امن SQL ارتقا بده.
- برای تست ساخت پروژه: `npm run check` و سپس `npm run build`.
